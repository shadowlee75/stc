스태커크레인 자동창고가 요구 물동량을 감당하는지, 감당 못 하면 몇 대가 필요한지를 화면에서 직접 돌려 보고 판정하는 프로그램입니다. 설치할 것이 없고, HTML 파일 하나를 더블클릭하면 열립니다.

5분 만에 시작

아무것도 설정하지 않아도 차체 저장 설비 Rev.0 조건이 미리 들어 있습니다. 아래 세 번만 하면 첫 결과가 나옵니다.

첫 실행

지금 설비가 1대로 되는지 본다

  1. dist\STC_ASRS_시뮬레이터_v0.1.html 파일을 더블클릭합니다. 크롬이나 엣지에서 열립니다.
  2. 맨 처음 보이는 ① 모델 화면 오른쪽에 “검증 통과” 초록 글씨가 있는지 봅니다. 빨간 글씨가 있으면 그 문장이 원인입니다.
  3. 왼쪽 위 파란 버튼 단일 실행 → ③ 통계 를 누릅니다.
나오는 것 · ③ 통계 화면으로 넘어가면서 큰 글씨로 OK 또는 NG 판정이 뜨고, 그 아래에 왜 그런지 사유가 줄줄이 나옵니다. 기본 조건은 NG가 정상입니다. 크레인 1대로는 요구 물동량 185건/h를 감당하지 못한다는 것이 이 설비의 원래 결론입니다.

여기까지 되면 프로그램은 정상입니다. 다음으로 궁금한 것이 “그럼 몇 대가 필요한가”라면 3장 작업 레시피의 레시피 B로 바로 가시면 됩니다.

1

화면 지도

화면은 늘 같은 구조입니다. 위쪽에 제목줄, 그 아래 탭 7개, 그리고 본문입니다. 본문은 탭에 따라 한 칸이거나 두 칸입니다.

  • 1제목줄 정보 블록 — 지금 어떤 시나리오인지, 마지막 실행이 OK였는지 NG였는지, 배치 실행이 빠른 방식(Web Worker)으로 도는지를 항상 보여줍니다.
  • 2탭 7개 — 작업 순서대로 왼쪽부터 배치돼 있습니다. 조건을 넣고(①), 눈으로 보고(②), 숫자를 읽고(③), 비교하고(④⑤), 계산서와 대조합니다(⑥).
  • 3왼쪽 = 입력 — 위에서 아래로 실행 조건, 랙, 크레인, 이재, 운영 정책, 판정 목표, 그리고 스테이션 표와 크레인·존 표입니다.
  • 4파란 버튼 — 이 프로그램에서 파란 버튼은 “실제로 돌린다”는 뜻입니다. 흰 버튼은 준비·저장 같은 보조 동작입니다.
  • 5오른쪽 = 검증과 JSON — 입력이 말이 되는지 즉시 검사한 결과와, 조건 전체를 담은 텍스트(JSON)입니다. 왼쪽 폼을 고치면 이 텍스트가 자동으로 따라 바뀝니다.
검증 칸부터 봅니다. 빨간 글씨(오류)가 하나라도 있으면 실행 버튼을 눌러도 돌지 않습니다. 노란 글씨(경고)는 돌아가되 주의하라는 뜻이고, 파란 글씨는 참고 정보입니다.

2

탭 7개, 언제 쓰나

탭이럴 때 씁니다여기서 얻는 것
① 모델조건을 넣거나 고칠 때검증 결과, 존별 입출 수지
② 3D 애니메이션크레인이 실제로 어떻게 움직이는지 눈으로 볼 때동작 확인, 어디서 막히는지 감
③ 통계한 조건의 결과 숫자를 읽을 때OK/NG 판정, 달성률·가동률·대기·분포
④ 실험기두 가지 이상 방식을 공정하게 비교할 때평균 ± 95% 신뢰구간 비교표
⑤ 최적화기“몇 대면 되나”를 자동으로 찾을 때추천 설계, 순위표, 불가 사유
⑥ 해석식기존 계산서(FEM 9.851)와 맞는지 확인할 때이용률·필요 대수, 시뮬과의 차이 Δ
⑦ 도움말모델 가정·지표 정의가 헷갈릴 때프로그램 안에 들어 있는 요약 설명
탭을 옮겨도 조건은 유지됩니다. 다만 입력을 고치면 이전 실행 결과는 지워집니다. 조건이 바뀌었는데 옛 결과를 보여주면 잘못 판단하게 되기 때문입니다. 고쳤으면 다시 실행하시면 됩니다.

3

작업 레시피

실무에서 실제로 하게 되는 다섯 가지입니다. 순서대로 누르기만 하면 됩니다.

레시피 A

이 조건이 되는지 안 되는지만 빨리 본다

  1. ① 모델 오른쪽 검증 칸에 빨간 오류가 없는지 확인합니다.
  2. 파란 버튼 단일 실행 → ③ 통계 를 누릅니다.
  3. ③ 통계 맨 위 달성률 큰 숫자와, 그 아래 OK / NG 상자를 읽습니다.
  4. NG면 상자 안 목록이 탈락한 이유 전부입니다. 하나씩 대응하면 됩니다.
걸리는 시간 · 8시간 운전을 약 0.05초에 계산합니다. 버튼을 누르면 바로 결과가 뜹니다.
레시피 B

크레인이 몇 대(통로 몇 개) 필요한지 찾는다

  1. ⑤ 최적화기 탭으로 갑니다.
  2. 탐색 공간에서 병렬 통로 수 1, 2, 3 을 체크합니다. 나머지는 처음엔 기본값 그대로 둡니다.
  3. 파란 버튼 최적화 실행 을 누릅니다.
  4. 파란 테두리 추천 설계 카드에 최소 대수가 나옵니다.
  5. 그 아래 순위표에서 더 적은 대수가 왜 안 되는지 사유를 확인합니다.
기본 조건의 답 · 통로 3개면 가동률 약 70%로 OK, 1대와 2대는 NG입니다. 이는 계산서의 “필요 대수 2.52 → 3대”와 같은 결론입니다.
레시피 C

운영 방식을 바꾸면 나아지는지 비교한다

  1. ④ 실험기 탭으로 갑니다.
  2. 비교하고 싶은 항목만 두 개 이상 체크합니다. 예: 운전 모드에서 SC-return 과 DC.
  3. 반복 R 을 10으로 둡니다. 같은 조건을 난수만 바꿔 10번 돌린다는 뜻입니다.
  4. 행렬 생성 → 실행 순서로 누릅니다.
  5. 결과표에서 두 줄의 숫자를 비교합니다. 뒤에 붙은 ± 값 범위가 서로 겹치면 차이가 확실하지 않다는 뜻이니, R을 20~30으로 올려 다시 돌립니다.
공정한 비교입니다 · 같은 반복 번호끼리는 똑같은 난수를 씁니다. 그래서 두 방식의 차이가 “운이 좋았다”가 아니라 실제 방식 차이로만 나옵니다.
레시피 D

우리 현장 숫자로 바꾼다

  1. ① 모델 왼쪽 폼에서 랙 치수와 크레인 속도를 우리 설비 값으로 고칩니다. 단위는 각 항목 옆에 적혀 있습니다.
  2. 스테이션 표에서 입출고 위치(x, y)와 물동량(건/h)을 고칩니다. 줄이 모자라면 스테이션 추가.
  3. 크레인·존 표에서 존 범위가 스테이션을 모두 품는지 확인합니다.
  4. 오른쪽 검증 칸이 초록이 될 때까지 고칩니다.
  5. JSON 저장 으로 조건 파일을 보관해 둡니다. 다음에 JSON 열기 로 그대로 불러옵니다.
되돌리고 싶으면 · 프리셋을 다시 불러오기 하면 원래 조건으로 초기화됩니다.
레시피 E

기존 계산서와 맞는지 대조한다

  1. ⑥ 해석식 탭을 엽니다. 계산서와 같은 방식(FEM 9.851 준용)으로 계산한 표가 이미 나와 있습니다.
  2. 이용률 U, 필요 대수 N, 복합사이클 가중평균이 계산서 값과 같은지 봅니다.
  3. ③ 통계 에서 단일 실행을 한 번 한 뒤 다시 ⑥ 해석식 으로 오면, 맨 아래 시뮬레이션 대조 표에 차이 Δ가 표시됩니다.
판단 기준 · Δ가 ±5% 안이면 초록으로 표시되고 정합입니다. 기본 조건에서 복합사이클은 −1.8%로 계산서와 잘 맞습니다.

  • home — SC-return 모드에서 일 끝내고 돌아갈 자리
  • x0 · y0 — 시작 위치
존을 나눌 때 가장 많이 걸리는 함정. 각 존에는 출고 스테이션이 하나는 있어야 합니다. 없으면 그 존은 물건이 들어가기만 하고 나오지 못해 결국 꽉 찹니다. 프로그램은 이것을 빨간 오류로 잡아 줍니다. 이건 프로그램 결함이 아니라 그 배치가 물리적으로 성립하지 않는다는 뜻입니다. 반대편에 출고구를 하나 더 두면 해결됩니다.

결과 읽는 법

OK / NG 판정 — 다섯 가지를 모두 통과해야 OK

  • 1달성률이 목표 이상요구한 물동량을 실제로 처리했는가
  • 2최대 가동률이 ρ 이하여유 없이 100%로 돌면 조금만 틀어져도 무너집니다
  • 3대기열이 늘어나지 않음시간이 갈수록 줄이 길어지면 언젠가는 반드시 터집니다
  • 4평균 대기열이 상한 이하스테이션 앞에 쌓이는 양
  • 5저장 블로킹·처리 불가가 없음빈 셀이 없어 못 넣거나, 꺼낼 수 없는 작업이 생기지 않았는가

맨 위 숫자 카드

카드읽는 법
요구 대비 달성률가장 중요한 숫자입니다. 100%에 가까워야 정상. 45%면 요구의 절반도 못 한 것입니다
입고 / 출고 처리실제 처리량(건/h)과 요구량을 나란히 보여줍니다. 한쪽만 낮으면 그쪽이 밀린 것입니다
크레인 가동률실제로 일한 시간 비율. 100%면 쉴 틈이 없다는 뜻이고 이미 한계입니다
평균 대기스테이션에서 크레인을 기다린 평균 시간(초). 수천 초가 나오면 사실상 방치된 것입니다
라인 정지시간현장에서 실제로 라인이 멈춘 시간입니다. 입고 버퍼가 꽉 차 상류가 물건을 못 보낸 시간의 합. 관리자에게 가장 와닿는 숫자입니다
재고랙이 얼마나 찼는지. 100%에 닿으면 더 넣을 곳이 없어 크레인이 멈춥니다

크레인 상태 색

3D 화면과 통계 그래프에서 같은 색을 씁니다.

  • 파랑 — 공차 주행 · 짐 없이 가지러 가는 중
  • 초록 — 적재 주행 · 짐을 싣고 이동 중. 이게 많으면 건강한 상태입니다
  • 주황 — 이재 · 포크로 넣고 빼는 중. 지나치게 크면 포크가 병목입니다
  • 빨강 — 블로킹 / 기아 · 넣을 빈 셀이 없거나 꺼낼 재고가 없어 못 움직이는 상태. 나오면 원인을 찾아야 합니다
  • 회색 — 유휴 · 할 일이 없어 쉬는 중. 여유가 있다는 좋은 신호입니다

그래프이렇게 보면 됩니다
시간당 처리 물동량점선이 요구량입니다. 실선이 점선에 붙어 평평하면 정상. 점선 아래에서 벌어지면 능력 부족
스테이션 대기열 길이평평해야 정상입니다. 계속 우상향이면 포화이고, 시간을 늘려도 절대 안정되지 않습니다
랙 재고율100%나 0%에 닿으면 그 시점부터 크레인이 막히거나 굶습니다
대기·사이클 히스토그램평균만 보면 놓치는 최악의 경우가 보입니다. 오른쪽 끝에 몰려 있으면 일부 작업이 심하게 밀린 것입니다

± 붙은 숫자(95% 신뢰구간)

④ 실험기와 ⑤ 최적화기의 결과는 62.2 ± 4.5 처럼 나옵니다. 여러 번 돌린 평균이 62.2이고, 참값이 57.7~66.7 사이일 가능성이 95%라는 뜻입니다.

  • 두 설계를 비교할 때 ± 범위가 겹치면 차이가 있다고 말하기 어렵습니다.
  • 확실히 가리고 싶으면 반복 R을 늘립니다. R을 4배로 늘리면 범위가 대략 절반으로 좁아집니다.

자주 막히는 곳

증상원인과 해결
실행 버튼을 눌러도 아무 일이 없다검증에 빨간 오류가 있습니다. ① 모델 오른쪽 검증 칸의 첫 줄을 읽고 그것부터 고칩니다
“출고 스테이션이 없어 반출 불가”존을 나눴는데 그 존 안에 출고구가 없습니다. 존 범위를 넓히거나 그쪽에 출고 스테이션을 추가합니다
“존 중첩”크레인 두 대의 x·y 범위가 겹칩니다. 경계값을 맞춰 딱 붙게 하되 겹치지는 않게 합니다
결과가 갑자기 사라졌다입력을 고치면 이전 결과를 지웁니다. 다시 단일 실행 하시면 됩니다
3D가 안 움직인다다른 탭으로 가면 자동으로 멈춥니다. ② 3D 로 돌아와 재생 을 누릅니다
창을 다른 프로그램으로 덮으면 시계가 멈춘다정상입니다. 브라우저가 화면을 안 그릴 때는 시간도 진행하지 않습니다
CSV 저장이 안 된다공유 링크(웹) 버전은 보안상 파일 저장이 막혀 있어 복사용 창이 대신 뜹니다. 파일로 받으려면 로컬 HTML 파일 버전에서 하시면 됩니다
실험기가 오래 걸린다설계 조합 수 × 반복 R 만큼 돌립니다. 조합을 줄이거나 R을 낮춥니다. 보통 수십 건은 1초 안에 끝납니다
대기시간 그래프 오른쪽 끝에만 막대가 몰린다포화 상태라 대기가 측정 범위를 넘은 것입니다. 그 자체가 “능력 부족”이라는 결론입니다
계산서와 사이클타임이 5~8% 다르다작은 랙(5×6)에서는 정상 범위입니다. 계산서는 랙을 연속 면으로 가정하고 시뮬은 실제 칸 단위로 계산하기 때문입니다
